## 1. Terraform 개요
- Hashicorp 사에서 만든 IaC(Infrastructure as a Code ~ `Ansible`, `Vagrant`, `AWS CloudFormation` 등) 오픈소스 도구.
- IaC의 장점
  - 매번 똑같은 환경을 그대로 재현 가능하다. (개발자들끼리 환경을 통일하여 **"일관성"** 을 유지할 수 있다)
  - Human-Error 발생 확률을 감소시킨다.
  - On-Demand 형태로 Infrastructure를 제공한다.
  - 무결성 확보
    > tfstate,  lock 파일(프로바이더의 버전 유지 및 관리를 위한 파일) 활용.
    
    
  - Idempotent(멱등성)
    > 동일한 작업을 여러번 수행해도 결과가 동일한 특성
  

- `HCL` 언어를 사용하며, Infrastructure의 **"Desired State"** 를 선언적(Declarative) 문서로 작성한다.
  > 넓은 범주에서, Dockerfile, Docker-compose.yaml, Kubernetes yaml 파일도 IaC로 볼 수 있다.


### Terraform은 클라우드 인프라 프로비저닝 및 관리에 특화된 도구이다. 
#### 네트워크 구축부터 도메인 배포까지 한 번에 가능하다!


> Ansible : 인프라 프로비저닝보단 이미 만들어져있는 인프라를 관리하는 것에 특화된 도 


#### Terraform Cloud
- `Github` 같은 레포지토리를 통해 `tfstate` 및 `lock` 파일을 공유하는 웹 플랫폼
  - 협업하는 팀원들과 현재 인프라의 상태를 공유하고 무결성을 보장할 수 있다!


#### pulumi
- 내게 익숙한 프로그래밍 언어로 인프라 프로비저닝 할 수 있는 도구
  - 내가 만약 특정 프로그래밍 언어를 잘 다룬다? `pulumi`를 통해 IaC를 구현해도 무방하다.


### ★ tfstate ★
- Insfrastructure의 현재 상태(**"Current state"**)를 담고 있는 파일.
- 현재 상태 정보를 담고 있긴 하지만, 이것 자체가 Infrastructure라는 뜻은 아니다.
  - `Desired State`와 `Current State`가 정확히 일치한다는 보장은 없다!

    
※ 따라서 항상 Infrastructure의 실제 현재 상태와 `tfstate` 상의 현재 상태가 동일하도록 유지해야 한다! <br>

## 2. VSCode에 Terraform 설치 및 활용법
- Windows에 설치하려면, Java와 유사하게 `C:\bin` 경로와 같이 바이너리 파일 모아둔 폴더로 다운로드 후 ***환경 변수*** 잡아야함!


#### 일반적인 Terraform 워크스페이스 구조
- 루트 디렉토리
  - `root.tf` : 각 모듈을 활용하여 실제 IaC를 수행하는 메인 파일.

- 각 모듈 별 디렉토리
  - `main.tf` : 모듈을 구성하는 메인 파일. 주로 리소스(클래스나 함수로 생각해도 무방)를 정의.
  - `variables.tf` : 각종 변수들을 모아놓음.
  - `locals.tf` : 해당 모듈에서"만" 유효한 변수를 모아놓음.
  - `outputs.tf` : 특정 모듈에서 생성한 리소스를 다른 모듈에서 참조하거나 가져다 쓰고 싶을때 선언.

---

### Terraform 주요 명령어
- `terraform init` : 말 그대로 초기화. 명시된 모든 프로바이더(라이브러리) 및 모듈을 검색후 다운로드 및 설치.
  - 명령어 입력 전, 전역 설정이 작성된 `tf` 파일이 있어야 함!


- `terraform plan` : **"Desired State"** ~ **tfstate의 "Current State"** 간 차이점을 보여주고 시뮬레이션을 수행.


- `terraform apply` : `tf`파일의 변경 사항을 실제 인프라에 적용하여 리소스를 생성,수정,삭제. (실제 수행 명령)
  - `--auto-approve` 인자값 추가 시 별도 명령 없이 강제로 인프라를 적용함


- `terraform destroy` : `tf`파일에 명시된 인프라 구성 사항을 바탕으로 삭제. 마찬가지로 `--auto-approve` 명령어 입력 가능



### ※ 주의 사항
- `eksctl` 명령을 칠때와는 다르게, AWS EKS 생성 시 IAM Access Entry에 자동으로 IAM Role이 생성되지 않는다!
  - 수동으로 IAM Role 추가가 필요하다. (`principal arn` 지정 → Type : `Standard` → Policy : `AWSEKSClusterAdminPolicy`)
